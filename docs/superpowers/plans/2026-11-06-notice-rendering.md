# 公告显示修复实施计划

**目标：** 公告详情正确呈现后台 Markdown，正文不再被订阅菜单增强脚本修改。

**方案：** 前端使用固定版本 Marked 解析 Markdown，再使用 DOMPurify 清洗 HTML；依赖随主题部署，不依赖第三方 CDN。保留已有 HTML 公告的安全排版。订阅项只在真实 Naive UI 菜单列表中查找，禁止回退到任意文本容器。正文使用独立排版样式，保持 14px 字号。

- [ ] 新增回归测试，证明原代码不能渲染标题、粗体和列表，且会误命中包含客户端名称的公告。
- [ ] 修复公告渲染和订阅项定位，同步 theme/public 资源及缓存版本。
- [ ] 验证 Markdown、旧 HTML、安全清洗、依赖失效回退、真实订阅项定位及正文保持原样。
- [ ] 运行前端回归和 Horizon provisioning 门禁，提交推送并核对对应 CI/镜像。
- [ ] 核对生产基线，备份后逐文件部署；检查公网资源、真实 Chrome 公告、全部业务消费者、三次队列趋势与新 SSH 会话。
