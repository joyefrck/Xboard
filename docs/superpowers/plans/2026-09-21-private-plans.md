# 私人定制套餐实施计划（简化版）

用户已确认：保持原套餐卡片和购买流程；后台手工创建实体专属套餐，填写绑定用户后保存即自动分配并开通（按用户最新要求）。

- 套餐增加普通、私人定制（待人工开通）、用户专属三种类型；专属套餐绑定用户且不可公开销售。
- 定制付款后进入待开通，停止原套餐，保留购买周期；管理员分配专属套餐时开始计时。
- 普通转定制沿用折抵；定制转普通不得折抵；专属续费原到期日顺延。历史定制订单永久排除折抵。
- 在原套餐编辑与用户编辑中增加最小字段及提示；用户侧沿用卡片，仅补状态与购买提示。
- 后端校验所属用户、独占权限组和节点；串行处理付款与人工分配，重复通知不重复开通。
- 用隔离 SQLite 测试生命周期、折抵、权限与重复操作；运行现有相关测试，检查镜像资源一致及浏览器布局。

不部署、不推送、不修改已有业务数据。当前分支 master；保留未跟踪的知识库图片。

## 使用方式

1. 套餐管理 → 添加套餐，类型选「私人定制（待人工开通）」。名称、说明和周期价格均可修改；开启显示和新购后，用户在原套餐卡片中购买。
2. 用户支付后显示待开通，原主套餐结束。创建独立权限组及只属于该组的节点，再添加「用户专属套餐」，填写绑定用户邮箱、权限组、流量与续费价格。专属套餐自动隐藏且禁止其他用户购买。
3. 保存专属套餐时，系统自动分配给绑定用户并从此刻按原订单购买周期计时，自动配置权限和流量。用户管理中会直接显示结果，无需再次选择套餐。
4. 用户续费走自己的专属套餐；换购高级、旗舰时不折抵专属套餐余值。待开通阶段同样不折抵。

## 套餐列表分类 Tab

用户追加要求：普通套餐、私人定制、用户专属使用三个 Tab，默认普通套餐，保持现有样式。

实现：复用后台 Radix Tabs 组件；按 plan_type 过滤表格，旧数据按 standard 处理；切换时清空搜索、选择及分页。排序时清空表格筛选与列排序，仅重排当前类型在完整列表中的位置，保存仍提交完整 ID 顺序；排序未保存时禁用 Tab 切换。验证三类隔离、默认选中和跨类型排序保持。

## 保存专属套餐自动开通

用户要求取消重复绑定操作。`PrivatePlanService::savePlan` 在同一事务中锁定用户、保存套餐并完成待开通订单的分配；失败回滚。已开通的同一套餐再次保存不重置有效期、用量或待重置时间；原强制同步配置选项仍有效。无待开通订单且不持有此套餐时禁止凭保存免费开通，节点未准备好则提示先配置。

验证：隔离数据库生命周期测试 43 项断言通过，覆盖新建自动开通、已有套餐保存开通、重复保存保持周期和用量、无可用节点与无已付订单的原子回滚。

## 邮箱绑定与搜索（2026-09-22）

绑定字段改为注册邮箱，保存时由后台精确解析成账号 ID，已有归属仍存 ID 且不可转移。后台套餐接口批量附加 owner_email，公开目录不返回此信息。用户专属列表显示邮箱，搜索框同时匹配套餐名称与邮箱，支持部分匹配且不区分大小写。

验证：48 项后端生命周期断言、34 项相关前端测试通过。Chrome 本地实页确认邮箱显示、搜索命中和编辑回填，未提交或更改用户的业务数据。
