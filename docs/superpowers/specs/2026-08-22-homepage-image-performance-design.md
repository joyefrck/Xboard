# 官网首页图片性能优化设计

## 目标

在不改变官网首页视觉构图、文案和导航行为的前提下，显著降低首页图片传输体积，并让非首屏图片延后加载。优化先部署到本地 Docker 测试环境，不推送远端或发布生产。

## 当前基线

首页实际引用 8 张本地图片：

- Logo：`80×80` JPEG，约 4.7 KB，位于首屏。
- 三张痛点配图：文件名后缀为 `.png`，实际编码为 `640×640` JPEG，共约 98 KB。
- 四张用户头像：文件名后缀为 `.png`，实际编码为 `640×640` JPEG，共约 138 KB，但页面仅以 `48×48` 展示。

除 Logo 外的 7 张图片合计约 248 KB。三张痛点图已有 `loading="lazy"`，四张头像仍为默认立即加载。图片标签缺少统一的异步解码和固有尺寸声明。本地 Octane 静态响应不包含 `Cache-Control`，但此次不把静态文件改为 PHP 动态响应，以免用缓存头换来更高的每次请求开销；生产静态缓存策略留给后续部署层专项处理。

## 方案比较

### 方案一：原文件原尺寸重新压缩

实现简单，但头像仍传输远超展示需求的 `640×640` 像素，收益有限；继续使用错误的 `.png` 后缀也会让响应类型与实际 JPEG 编码不一致。

### 方案二：WebP 与按展示需求缩放，采用

三张痛点图保持 `640×640` 并转为 WebP；四张头像缩放到 `96×96` 后转为 WebP，满足 `48×48` 展示下的 2 倍像素密度。页面直接引用 WebP，原文件保留但不再下载。该方案兼顾压缩率、解码速度、浏览器兼容性和实现复杂度。

试压缩结果显示，7 张优化文件约 68 KB，相对原文件约减少 72%。

### 方案三：AVIF、WebP、原图三层 `<picture>`

AVIF 还能进一步降低部分体积，但会增加 14 个新资产、HTML 复杂度与图片解码成本。当前图片总量不大，额外收益不足以抵消维护成本，因此不采用。

## 资产生成规则

- `pain-google-ip.webp`、`pain-ai-tools.webp`、`pain-streaming.webp`：保持 `640×640`，使用 `cwebp -q 80 -metadata none`。
- `avatar-pm.webp`、`avatar-tiktok.webp`、`avatar-educator.webp`、`avatar-freelancer.webp`：缩放到 `96×96`，使用 `cwebp -q 78 -resize 96 96 -metadata none`。
- `elephant-route-logo.jpg` 保持不变；它已经是 `80×80`、约 4.7 KB，转换收益不足。
- 原 `.png` 文件和 `elephant-route-logo-original.jpg` 不删除，确保历史兼容和可逆恢复。

## HTML 加载策略

- Logo 保持首屏立即加载，增加 `width="40"`、`height="40"`、`decoding="async"` 和 `fetchpriority="high"`。
- 三张痛点图引用 WebP，增加 `width="640"`、`height="640"`、`loading="lazy"`、`decoding="async"` 和 `fetchpriority="low"`。
- 四张头像引用 `96×96` WebP，增加 `width="48"`、`height="48"`、`loading="lazy"`、`decoding="async"` 和 `fetchpriority="low"`。
- 固有尺寸与现有 CSS 展示尺寸一致，避免图片加载前后布局偏移。

## 性能预算与自动验证

新增聚焦测试，固定以下契约：

- 7 张优化资产必须存在并具有 RIFF/WebP 文件签名。
- 7 张优化资产总大小不超过 80 KiB。
- 优化资产总大小不超过对应原文件总大小的 35%。
- 首页不得再引用 7 张旧 `.png` 文件。
- Logo、痛点图和头像必须包含各自约定的尺寸、加载、解码和优先级属性。
- 原始回退资产仍然存在。

## 本地验收

代码测试通过后不需要重启 Octane，因为本次只修改和新增 `public/` 静态文件；仍需通过本地 Docker 验收：

- 首页与 7 张 WebP 均返回 HTTP `200`，WebP 响应类型正确。
- HTTP `Content-Length` 合计符合 80 KiB 预算。
- 浏览器首页首屏布局不变，滚动后 7 张优化图都完成加载且没有缺图。
- 浏览器控制台没有新增 error 或 warn。
- 定价、服务条款、隐私政策、退款说明和 `/app` 行为不受影响。

## 风险与回滚

- WebP 已被当前主流桌面与移动浏览器支持；保留原始文件可在发现兼容问题时快速切回。
- 头像缩到 `96×96` 只服务现有 `48×48` 展示；如果未来放大头像，需要同时提高源尺寸和性能预算。
- 回滚只需恢复 `public/landing/index.html` 并删除新增 WebP 文件，不涉及数据库、容器配置或持久化数据。
