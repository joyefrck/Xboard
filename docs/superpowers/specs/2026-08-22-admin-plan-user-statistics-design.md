# 套餐管理用户统计修复设计

## 背景

套餐管理接口当前通过 `Plan::users()` 统计 `users_count`，并仅按 `expired_at` 统计 `active_users_count`。这套实现早于可叠加流量包账本：周期套餐过期后仍保留 `v2_user.plan_id`，而一次性流量包自 2026-06-19 起主要记录在 `v2_user_traffic_packages`。因此，现有数字既不能表示累计购买人数，也会遗漏绝大多数流量包持有人；绿色数字还会包含封禁或流量已经耗尽的用户。

## 目标

- 保留管理端现有接口字段 `users_count` 和 `active_users_count`，避免前端/API 契约变化。
- 周期套餐统计当前仍归属该套餐的用户，同时让“当前可用”与实际服务资格一致。
- 一次性流量包统计独立流量包账本，并兼容迁移前仍通过 `v2_user.plan_id` 表示的历史用户。
- 同一用户同时出现在当前套餐归属和流量包账本时只计一次。
- 修正管理端提示语，准确描述两个数字的口径。
- 不修改用户、订单、套餐或流量包数据，不新增迁移。

## 方案比较

### 方案 A：用户归属与流量包账本合并去重（采用）

把 `v2_user.plan_id` 与 `v2_user_traffic_packages.plan_id` 统一为 `(plan_id, user_id, is_active)` 数据集，再按套餐聚合去重。

优点：兼容现有周期套餐、旧版一次性套餐和新版流量包账本；不依赖订单状态推断当前余额；同一用户不会重复计数。缺点：查询比原来的两个关联计数复杂，需要明确索引和回归测试。

### 方案 B：全部改用已完成订单

灰色数字统计已完成订单的去重购买用户，绿色数字再结合用户或余额判断。

优点：适合销售分析。缺点：试用、管理员手工分配和历史导入没有订单；订单也不能直接反映当前流量包余额，不符合套餐管理的持有/可用语义。

### 方案 C：保留旧查询，只修改提示语

优点：改动最小。缺点：仍会把 70G/180G 流量包显示为 28/8，无法解决已经确认的数据遗漏。

## 统计定义

### 总数 `users_count`

按 `plan_id` 对以下用户 ID 取并集并去重：

1. `v2_user.plan_id = plan.id` 的当前套餐归属用户，包括已过期用户。
2. `v2_user_traffic_packages.plan_id = plan.id` 的历史流量包持有人，包括余额已耗尽用户。

该字段表示“关联用户”，不表示订单数或累计销售额。

### 当前可用 `active_users_count`

用户满足以下任一条件时计入，并按 `(plan_id, user_id)` 去重：

1. 当前套餐可用：未封禁、套餐流量大于零、已用流量小于套餐流量，且未到期或长期有效。
2. 流量包可用：未封禁，账本状态为 `active`，且 `remaining_bytes > 0`。

同一用户同时拥有有效周期套餐和同 ID 的可用流量包时仍只计一次。

## 后端设计

`PlanController::fetch()` 使用一个只读聚合查询构造两个来源的 `UNION ALL`：

- `v2_user` 来源输出当前套餐归属及其可用状态。
- `v2_user_traffic_packages` 联接 `v2_user`，输出流量包归属及余额可用状态。

外层按 `plan_id` 分组，使用 `COUNT(DISTINCT user_id)` 计算总数，并使用条件 `COUNT(DISTINCT CASE WHEN is_active = 1 THEN user_id END)` 计算当前可用人数。聚合结果一次性加载并按套餐 ID 回填，避免逐套餐查询。

所有时间判断共享请求开始时取得的同一个 Unix 时间戳，避免一个请求内边界漂移。没有关联用户的套餐回填为整数 `0`。

## 前端设计

继续读取 `users_count` 和 `active_users_count`，不调整表格结构：

- 灰色提示标题改为“关联用户”，说明当前套餐归属或历史流量包持有人均计入，已过期/已耗尽仍保留在总数。
- 绿色提示标题改为“当前可用用户”，说明未封禁且周期套餐仍可用，或流量包仍有余额。
- 百分比文案从“活跃率”改为“可用率”。

## 性能与兼容性

- 聚合查询只读取用户 ID、套餐 ID、状态、到期时间和流量字段，不加载模型对象。
- 使用现有 `v2_user.plan_id`、流量包 `plan_id`/`user_id` 相关索引；实现时检查生产同版本迁移的索引定义。
- API JSON 字段名和类型保持不变，现有管理端无需新增请求。
- 对没有流量包记录的周期套餐，结果等价于按当前归属用户统计，但绿色数字会正确排除封禁及流量耗尽用户。

## 测试与验收

回归测试覆盖：

1. 周期套餐的有效、过期、封禁和流量耗尽用户。
2. 仅存在于流量包账本的用户。
3. 已耗尽流量包不计入当前可用。
4. 同一用户同时存在于两个来源时总数和当前可用数均不重复。
5. 无关联用户的套餐返回两个整数零。
6. 管理端仍使用原字段，并显示“关联用户”“当前可用用户”“可用率”。

本地验证至少包括聚焦回归测试、PHP 语法检查、完整 Node 测试、`git diff --check`；若仓库现有构建依赖可用，再执行管理端构建或等价静态产物校验。生产发布前另行执行数据库只读复算和页面验收，不在本地修复阶段直接改生产。
