# 后台用户流量包独立分区布局设计

## 背景

后台用户编辑抽屉已经支持独立发放流量包，但“当前流量包余额”“增加流量包”“增加流量”目前紧跟在套餐流量后、到期时间与订阅计划前。视觉顺序容易让管理员误以为这些字段属于普通套餐。

本次只调整管理端字段顺序和视觉分区，不改变接口、数据库、校验、发放或扣减逻辑。

## 最终字段顺序

普通套餐相关字段按以下顺序排列：

1. 订阅计划。
2. 到期时间。
3. 套餐流量。

随后增加一个独立流量包分区：

4. 顶部分割线。
5. 分区标题“独立流量包”。
6. 辅助说明“独立于套餐流量，不修改套餐及到期时间”。
7. 当前流量包余额，只读。
8. 增加流量包，选择流量包商品。
9. 增加流量，输入正整数 GB。

账户状态、佣金、限速、设备限制、管理员标识和备注等原有字段继续排在独立流量包分区之后，内部顺序不变。

## 视觉方案

采用“顶部横向分割线 + 小标题 + 弱化说明文字”。分割线建立套餐区域和独立流量包区域的边界；标题直接说明数据归属；说明文字使用次要文字颜色和较小字号，避免与表单标签争夺视觉层级。

不使用独立卡片，以免在窄抽屉中引入额外边框、内边距和嵌套层级。不只使用裸分割线，因为裸分割线无法说明两类流量的业务关系。

## 文案

在中文、英文、韩文管理端语言包中增加两个键：

- 分区标题：独立流量包。
- 分区说明：独立于套餐流量，不修改套餐及到期时间。

现有“套餐流量”“当前流量包余额”“增加流量包”“增加流量”文案保持不变。

## 行为边界

- 套餐流量仍写入 `v2_user.transfer_enable`。
- 独立流量包仍通过选择商品和输入 GB 新建 `v2_user_traffic_packages` 记录。
- 分割线和说明文字不参与表单状态及提交负载。
- 打开或关闭抽屉时，流量包商品和增加量仍按现有逻辑清空，避免重复发放。
- 当前流量包余额仍为只读汇总。

## 测试策略

更新管理端静态契约测试，按用户编辑函数中的实际位置验证：

1. `plan_id` 位于 `expired_at` 之前。
2. `expired_at` 位于 `transfer_enable` 之前。
3. 独立流量包分区标题位于 `transfer_enable` 之后。
4. 三个流量包字段按“余额、商品、增加量”排列，并位于分区标题之后。
5. `banned` 位于独立流量包字段之后。
6. 中文、英文、韩文均包含分区标题和说明。

执行管理端聚焦测试、现有流量包测试、全量 Node 测试、JavaScript 语法检查和 `git diff --check`。完成本地修改后重建 Web 容器，并验证本地后台返回新静态产物。
