# 订单折算退款到余额

用户指定订单列表末尾三点菜单、退款到余额、二次确认。后续明确：按未过期时购买新套餐的已有折抵逻辑折算退款，并回收对应套餐、流量和有效期。本次为代码及隔离验收，不发布生产。

## 范围与金额

周期订阅直接复用 OrderService 原有换套餐剩余价值计算，保留系统 surplus_enable、私有套餐不折抵及 change_order_event_id 的现有行为。周期订阅可能由新购/续费共同构成，因此从其中任一有效订单操作均针对当前订阅整体，预览列出所有关联订单；这些订单统一关闭为已退款。历史其他套餐订单不允许取消当前套餐，已折抵订单不能重复兑现。

独立流量包按该订单台账的剩余字节/总字节折算本金（包含余额支付，不含手续费），只清除对应台账，保留其他套餐和独立流量包。流量重置订单没有独立可回收权益，拒绝单独自动退款。已过期、无剩余价值、私有/不折抵套餐、充值、佣金已结算/发放中、用户有未完成订单均不自动退款。

## 预览与确认

预览展示套餐、折算依据、原始金额、折算退款、关联订单、即将回收的范围。退款原因必填；默认聚焦取消。签名加密报价有效 5 分钟，固定折算时刻；提交在锁内重算该时刻价值并比对权益快照，流量消耗、续费、套餐或订单状态变化要求重新核对。余额变化不使报价失效。超时重试先查原退款记录，避免重复入账。

## 事务与记录

按用户→订单→流量台账加锁，订阅关联订单也加锁，重查全部关联佣金和未完成订单。入账、回收、关闭订单、佣金作废、审计及关联关系在同一事务。

周期退款清除 plan_id、expired_at、transfer_enable、u/d、下次/上次重置时间、custom_pending_order_id、套餐权限组/限速/设备限制；若有另购独立流量包，恢复这些独立权益对应的访问配置。独立流量退款将对应台账剩余流量清零并置为耗尽，不改其他台账或订阅。

新增增量 migration 为退款表添加 snapshot，并建立唯一订单→退款记录关联表；同一订阅多笔订单共享一条退款审计，在任一关联订单详情均可查询。本次不修改已存在的初始迁移。

## 验证

对照直接调用已有换套餐计算结果；覆盖按时间/时间和流量取较小值、旧折抵价值、续费合并、历史订单、到期/流量耗尽、独立流量包按比例退款、只移除对应权益、报价篡改/到期/权益变化、幂等及全事务回滚。真实 MySQL 多进程验证同一订单和同一订阅不同订单并发只入账一次。浏览器检查预览、回收提示、失败后重新核对及退款审计。

## 用户订单与退款邮件（后续补充）

用户订单只将退款状态 5 显示为“已退款”；原金额保留并加删除线，下方相同字号红色显示 +40.00 元。API 返回专用 refund 摘要，隐藏管理员及余额历史等内部审计。合并退款按各关联订单有效价值权重分配到分，余数按最大余数分配，逐行金额之和等于实际一次入账总额；详情提供合并信息。

成功退款事务内保存逐单分配及邮件待发记录；提交后投递现有 send_email 队列。专用 job 复用发送与限流，锁定通知记录后发送，成功后记录 sent_at；重复请求/重复 job 不重复通知。调度器补发未成功投递的待发记录，发送失败按退避重试，金融退款不因 Redis/SMTP 故障撤销。SMTP 已接受后进程崩溃的分布式投递窗口仍可能重复，不能声称外部发送严格 exactly-once。

HTML 邮件使用响应式内联表格，默认与 classic 模板可用；自定义模板缺失时回退默认退款模板。包含订单编号、订单创建日期（北京时间）、原订单金额、退款金额、退款日期及“已退到站内余额”的说明；合并退款只发一封，列出关联订单及总计，日期/金额使用成功时快照，转义动态内容。未授权发送真实测试邮件，本次全部使用隔离数据与假邮件服务。

## 后台列表金额补充

后台退款状态统一显示“已退款”。已退款行金额显示 ¥50.00/¥40.00，原金额使用删除线，退款金额红色；未退款行保持原样。列表和详情读取逐单退款分配，合并退款不在每行重复展示整笔总额，未知金额不推测为零。
