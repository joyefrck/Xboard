# 个人中心登录设备与新 IP 改密验证

状态：用户已确认可信 IP 规则；本地实现与验收完成，尚未发布生产。范围为 Xboard 后端与 ElephantRoute 个人中心；不包含自动生产部署、客户端安装包发布或直接撤销生产用户会话。

## 用户需求

- 在个人中心现有页面增加登录设备列表，支持退出单个设备和退出全部设备。
- 网页与使用账号登录的 App 会话统一展示、统一撤销。
- 新 IP 发起修改密码时，弹窗要求邮箱验证码，后端必须强制校验，不能只检查旧密码。
- 延续当前页面布局与视觉风格，不改变余额、通知、订阅重置和注销账号功能。

## 已核对的现状

- Sanctum personal_access_tokens 是网页和 App 共用的账号会话载体，每次登录可能创建新的令牌。同一物理设备可以有多条会话。
- getActiveSession/removeActiveSession 已存在，但前者直接返回模型数组，后者只支持单条撤销；需要改成明确的安全输出字段，不能返回令牌摘要或 abilities 等内部信息。
- 历史会话没有登录 IP、User-Agent 或可靠 App 名称，不能补造历史来源。
- 改密、忘记密码目前不撤销会话，登录令牌默认可有效一年。
- 当前大象客户端使用令牌恢复登录，账号校验收到 401/403 时清除本地登录并停止移除托管配置；不会在收到服务端撤销的瞬间获得主动推送。
- 日志器直接记录 request()->all()。本次新增验证码和改密参数必须在写日志前脱敏。

## 方案选择

1. 推荐：账号范围内，以邮箱验证成功的 IP 为可信来源。30 天内该 IP 改密允许使用旧密码；新 IP、可信记录过期或无记录时额外要求邮箱验证码。
2. 每次改密都验证邮箱：规则更简单、更严格，但增加用户每次改密的操作。
3. 用登录会话创建时的 IP 作为可信来源：不采用。持有密码的人在新 IP 登录后会自动获得免邮箱改密资格，不能满足本次安全目的。

## 页面与设备展示

- 在设置卡片下、注销账号卡片上方增加全宽“登录设备”卡片，沿用 Aurora 玻璃效果、14px 正文和至少 36px 的操作按钮。
- 每条表示一个有效登录会话，展示客户端名称、系统或浏览器、当前设备标记、登录时间、最近活动时间，以及记录可用时的登录 IP／最近活动 IP。
- 根据服务端收到的 User-Agent 或客户端标识推断名称；App 明确提供身份时展示名称，否则显示“App 客户端”或“未知客户端”。这些标识可以伪造，只作展示，不用于授权或信任判断。
- 历史会话显示“历史会话／设备信息未知”，历史登录 IP 保持未知；首次观察到的新元数据不能冒充历史登录信息。
- 不把最近活动等同于实时在线。一个会话的退出按钮只撤销该条会话，不声称识别了唯一硬件设备。
- 单条“退出”和“退出全部设备”均有确认提示。退出当前会话或全部会话后，清理当前浏览器本地认证并转到登录页。
- 全部退出包含当前会话。不会修改订阅凭据，不承诺立即断开已建立的代理连接。
- 支持桌面与手机；加载、空列表、失败重试、按钮提交中状态清楚可见。

## 会话数据及撤销

- 为会话追加有长度上限的客户端、来源和活动元数据；有效会话列表排除已过期记录。
- 在签发令牌时记录元数据，在认证成功请求时更新最近活动 IP 等信息；写入节流，避免每次请求更新额外字段。
- 只信任经过已配置可信代理解析的客户端 IP，不能直接接受任意 X-Forwarded-For 或客户端提交的 IP。
- 单条／批量撤销必须限制为当前登录用户自己的会话；无效 ID、非本人 ID 不得影响其他账号。
- 列表仅返回展示所需的允许字段，不返回实际 token、token 哈希、任意原始请求头。

## 新 IP 改密验证

- 可信来源由专门的邮箱验证记录决定，使用服务端规范化的 IP；普通密码登录或携带令牌访问不会使 IP 自动可信。
- 首次上线不根据历史访问、历史会话或当前登录自动建立可信来源，所以所有账号首次改密可能需要邮箱验证码。
- 原密码仍然必须校验。新 IP 还必须完成邮箱验证码验证；前端收到明确的验证需求结果后打开模态框，不把是否弹窗作为安全边界。
- 验证码通过已登录账号的邮箱发送，不允许客户端指定收件邮箱。使用独立用途，不复用注册／找回密码的验证码缓存。
- 验证码随机生成，5 分钟有效，60 秒发送冷却，并设账号与 IP 发送上限、最多 5 次错误验证；重新发送后旧码失效。
- 验证挑战绑定账号、当前会话及请求 IP，使用一次后原子消费。并发重放、过期、切换账号或切换来源不得通过。
- 只有验证码与最终改密全部成功才记录该 IP 可信，期限 30 天。邮箱验证不会使其他 IP 可信。
- 验证框显示脱敏邮箱、发送／重发倒计时、验证码输入、确认与取消；取消不改密码。密码和验证码不进入持久化前端存储。
- 对外标题固定为“安全校验”，提示只保留邮箱验证码的操作指引；不展示触发来源、可信期限、验证码有效时长或精确风控阈值。服务端规则和内部审计保持完整。
- 直接使用 curl 或旧版前端调用改密接口也必须遵守相同验证规则。

## 改密与找回密码后的会话失效

- 前台改密与忘记密码成功后撤销所有旧会话，当前页面也重新登录；后台为用户设置密码时同步撤销该用户旧会话。
- 改密及会话撤销采用一致的事务／锁定边界，验证失败不改密码、不撤销会话；并发使用旧密码的登录不能在改密完成后继续遗留有效旧凭据会话。
- 本次调整只在后续发生相关操作时生效；部署迁移不自动撤销所有生产用户会话。
- App 在下次账号认证请求时感知撤销，现有版本和网络状态影响实际发现时间，不能宣称主动即时踢下线。

## 日志和审计

- 新增操作只记录事件、用户 ID、会话标识摘要、规范化来源、客户端类别和成功／失败原因等必要信息。
- 对 password、old_password、new_password、password_confirmation、email_code、验证码及登录令牌等字段递归脱敏，并防止 URI 查询参数或异常上下文再次带出秘密。
- 本轮不删除历史生产日志；既有敏感历史记录的处置另行保全证据后处理。

## 验收标准

- SQLite 隔离测试证明会话数据不泄露凭据、有效期过滤正确、本人单条／全部撤销有效、无法撤销他人会话。
- 新 IP 无码、错码、过期、超过次数、重放、跨账号／会话／IP 均不能改密；只有正确验证才能成功。
- 密码登录不能自动信任 IP；可信 IP 过期后再次要求验证；IPv4／IPv6 规范化和代理头伪造边界有覆盖。
- 改密／找回／后台改密后的旧令牌无法认证；并发旧密码登录不能留下有效旧会话；失败路径不发生部分更新。
- 日志测试确保密码、验证码、认证头、嵌套敏感值及 URI 参数不会明文输出。
- 本地浏览器以合成账号验证列表、当前会话、单条退出、全部退出、验证码弹窗各状态及手机布局，不使用生产账号做改密测试。
- theme 与 public 资源一致，缓存版本更新，相关现有测试及 git diff --check 通过。
- 若后续授权生产发布，使用 xboard-release-checks 完整执行迁移、实际配置／消费者、队列趋势及业务与页面验收；不能仅凭本地测试宣布上线完成。
