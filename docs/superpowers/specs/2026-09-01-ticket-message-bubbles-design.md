# 工单消息气泡统一设计

## 目标

用户端与系统管理后台采用一致的“本人消息靠右”交互语义：用户端的用户消息在右侧、管理员消息在左侧；管理后台的管理员消息在右侧、用户消息在左侧。每条消息明确显示发送者称谓，用户端显示“您/管理员”，管理后台显示“用户/管理员”，并通过不同底色快速区分双方。

## 视觉方案

- 用户消息：用户端右对齐、管理后台左对齐，使用浅青绿色背景、青绿色边框和深色正文。
- 管理员消息：用户端左对齐、管理后台右对齐，使用浅蓝色背景、淡蓝色边框和深色正文。
- 气泡最大宽度约为对话区的 78%，使用 12px 圆角和 14px 正文，长文本及文件名可安全换行或截断。
- 称谓和时间位于气泡上方的同一行；称谓使用 12px 中等字重，时间继续作为次要信息显示。
- 附件链接保持在对应消息气泡内，不改变鉴权打开方式、格式和大小显示。

## 两端语义

- `v2_ticket_message.is_admin` 持久化消息的发送入口角色，用户创建/回复写入 `false`，后台及 Telegram 管理员回复写入 `true`。
- 用户端使用消息的 `is_me` 判断角色：`true` 为用户，`false` 为管理员。
- 管理后台使用消息的 `is_from_admin` 判断角色：`false` 为用户并放在左侧，`true` 为管理员并放在右侧。
- 后台中、英、韩文案分别提供用户和管理员称谓，避免新增硬编码中文影响其他语言。

## 兼容性与边界

- 不修改工单接口和附件数据；Telegram 继续使用原有文本回复入口，但由服务层写入管理员角色。
- 新增布尔角色字段并按现有 `message.user_id != ticket.user_id` 关系回填可识别的历史管理员消息；同账号历史消息无法可靠恢复角色，保持用户消息语义。
- 不改变回复、关闭、上传、下载、轮询和滚动行为。
- 同步 ElephantRoute 的主题/public 文件、gzip、Brotli 资源和缓存版本。
- 不触及工作区内优惠券、流量包及其他未提交改动。

## 验证

- 静态回归覆盖两端角色方向、称谓、差异化颜色、附件仍处于气泡内及后台三语文案。
- 校验主题/public 字节一致、gzip/Brotli 解压一致、JavaScript 语法和 `git diff --check`。
- 重启本地 Web 服务后，在用户工单页和后台工单详情分别进行实际浏览器视觉检查。
