# 用户钱包充值设计（已确认）

用户于 2026-11-05 确认本方案，授权代码实现及验证。

## 目标与范围

为 ElephantRoute 用户中心增加余额充值。入口位于个人中心的“我的钱包”，以及仪表盘右上角头像左侧。两个入口跳转到同一个充值页面。

本次为代码实现及本地验证方案；生产发布需单独明确授权。

## 页面行为

- 个人中心保留现有钱包余额展示，增加“充值”按钮。
- 仪表盘头像左侧显示“账户余额：1.90 元”和“充值”按钮，余额显示实际金额并保留两位小数。窄屏允许换行，避免挤压头像和导航。
- 独立充值页建议使用 `#/wallet/recharge`，保留现有用户中心导航与 Aurora 样式。
- 第一步选择金额，只提供 100、200、500 元，不支持手动输入，默认选中 100 元。
- 第二步选择支付通道，使用现有 `/api/v1/user/order/getPaymentMethod` 返回的启用通道，保持接口顺序；接口当前按后台 `sort ASC` 排序。默认选中第一个可用通道。
- 页面底部展示充值金额、支付手续费、实付金额及“支付”按钮。金额与支付通道都选定后才允许付款。
- 无可用通道时显示“暂无可用支付通道”，禁止提交。加载失败提供重试；支付失败保留订单供用户继续支付或取消。
- 沿用现有购买须知，在进入充值页时确认，进入订单后不重复弹出遮挡付款二维码。
- 提交期间禁用支付按钮。付款后复用当前订单支付结果展示、状态查询及订单取消流程。
- 订单列表及详情将商品标记为“余额充值”，展示充值本金、手续费和状态；后台订单也应能识别充值类型。
- 充值成功后刷新钱包及顶部余额；从外部支付页面返回或重新聚焦页面时重新核实订单状态和余额。

## 金额与业务规则

- 充值本金固定为 10000、20000、50000 分，服务端强制校验，不信任前端金额。
- 手续费完全复用现有支付通道配置及取整方式：`round(充值本金 × handling_fee_percent / 100 + handling_fee_fixed)`，单位为分。
- 用户实际付款为充值本金加通道手续费；到账余额为充值本金。例如充值 100 元、通道手续费 2 元，则付款 102 元、余额增加 100 元。
- 充值不能用已有账户余额抵扣，不参与优惠券、套餐折扣、套餐折抵、到期延长、流量重置或用户等级调整。
- 建议充值环节不发邀请佣金，后续使用余额购买套餐或流量包时继续执行原有佣金规则，避免同一笔资金在充值与消费时重复计佣。此项随本方案确认。
- 沿用现有未完成订单限制：已有待支付或处理中的订单时，提示用户先处理原订单，不自动取消。

## 后端接入

推荐方案是在现有 `v2_order` 中增加充值订单类型和周期标识，套餐关联留空。新增专用充值下单接口，避免放宽原套餐订单参数校验；支付、回调、状态查询和取消继续共用现有接口。

备选方案是新建充值流水表及独立回调处理。它能单独组织充值记录，但会重复维护支付能力，本次不推荐。

涉及的现有代码边界：

- `app/Models/Order.php`：新增充值类型、周期标识与显示名称。
- `app/Services/OrderService.php`：创建充值订单，处理充值到账，保持付款、取消和重试兼容。
- `app/Http/Controllers/V1/User/OrderController.php` 与 `app/Http/Routes/V1/UserRoute.php`：新增充值下单入口，允许没有套餐关联的充值订单进入详情与支付流程。
- `app/Http/Resources/OrderResource.php`：确保充值类型、本金与金额可供页面展示。
- 用户及后台订单展示：兼容没有套餐关联的充值订单，避免空白名称或空对象错误。

下单在事务中锁定用户，检查未完成订单并写入充值订单，避免重复点击和并发下单绕过限制。支付时仍检查支付通道是否启用。

回调先沿用现有支付校验与 `pending → processing` 状态更新；入账时在同一事务内锁定订单和用户，仅对处理中的充值订单加余额并标记完成。重复回调和重复执行处理任务不得重复入账。失败应回滚，继续由现有订单处理任务重试。

充值订单只改变用户余额及订单状态，不授予套餐、流量包或 Telegram 群权益。检查所有共享订单消费者，避免空套餐关联导致支付插件、通知、统计或后台页面异常。

## 前端接入

沿用现有主题结构。当前用户中心路由和部分页面在 `theme/ElephantRoute/assets/umi.js` 中，样式及增强能力由 `elephant-route-dashboard-v2.*`、`elephant-route-pages-v2.*` 提供。实现时复用现有登录状态、请求方式、支付结果处理和订单组件。

所有主题资源同步到 `public/theme/ElephantRoute`，保持内容一致，并更新两份 `dashboard.blade.php` 的资源版本。常规文字和按钮使用 14px，按钮至少 36px 高，保留当前品牌资产与玻璃背景样式。

## 验收

1. 两个充值入口进入同一页面，三个金额和当前启用支付通道均可选择，通道顺序与套餐支付一致。
2. 固定手续费、比例手续费、两者组合及零手续费均与服务端现有算法一致；切换通道同步更新实付金额。
3. 非法金额、未登录、他人订单、停用通道、并发下单和重复点击不能绕过校验。
4. 成功支付只增加充值本金；重复回调、重复处理任务只入账一次；失败、取消及过期订单不入账。
5. 充值后套餐、有效期、流量、限速、设备数、佣金与群权益不受充值动作影响。
6. 用户及后台订单能正常展示充值记录，套餐和流量包原有支付流程回归通过。
7. 浏览器检查桌面及手机布局、无通道、请求失败、支付处理中、支付成功、返回页面和余额刷新场景。
8. 运行相关 PHP 业务测试、Dashboard 2.0 与页面测试、主题镜像一致性检查及 `git diff --check`。

若后续授权生产发布，所有改动均执行完整 Xboard 发布检查，包括实际生效配置、全部业务 worker、队列趋势和线上验收。
