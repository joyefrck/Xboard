# 工单 AI 审核与黑名单

用户已确定：DeepSeek 自动判断文字辱骂、人身攻击、恶意攻击；首次工单禁言七天，到期后再次违规永久封禁整个账号。无用户申诉入口，不处理图片。保留现有管理员封号功能，在用户管理的账户状态下拉框中增加工单禁言；黑名单不提供封号按钮或弹窗。

审核覆盖创建和回复（包括提现工单入口），先审核再写入正式工单、发送邮件或 Telegram。输入包含当前文字和有限的历史上下文；历史言论不能当作本次违规证据。正常投诉、差评、退款要求及引用他人言论不直接构成违规。模型只能返回分类、原因和当前文字中的证据，处罚由服务端固定规则执行。

使用同步审核，失败自动重试一次，仍失败返回明确的稍后重试提示；不落正式工单、不计违规。这样保持现有客户端提交接口，不引入无人处理的待审队列。网络请求在数据库事务外执行；判定完成后锁定用户行，重新检查禁言/封禁状态，再原子写入处罚或工单，避免并发触发两次处罚。

用户表保存禁言截止时间和历史违规次数；独立记录表保存原文、有限上下文、证据、AI 原因、处罚、来源、操作人及时间。记录不依赖工单外键，不被十四天工单清理删除。七天到期按时间判断自动恢复，无需计划任务清除历史次数。永久封号复用 banned，撤销登录令牌；节点通过现有授权同步机制移除用户。

后台用户管理下增加黑名单子菜单：邮箱搜索、禁言中/已解禁/账号封禁筛选、分页、证据详情。用户编辑中的账户状态包含正常、封禁、工单禁言；选择工单禁言生效七天，选择正常解除当前限制，但保留历史。重复保存禁言不延长期限。手动禁言作为既有处罚计入再犯升级。现有用户编辑及批量封号也写入统一记录。无用户申诉功能，现有管理员解封能力继续保留。

API 密钥只保存在被 Git 忽略的服务端环境变量。使用官方 API 当前可用的 deepseek-flash，配置项保留模型可替换性。管理员接口只返回是否已配置，不返回密钥。仅用合成样本验证真实接口，不向 AI 上传本地数据库内容。

AI 自动封禁允许管理员覆盖：在用户管理把账户状态改为正常即可解除账号封禁和工单限制。保留违规历史和证据，记录管理员操作；旧登录会话不恢复，用户重新登录即可。解封后正常提交不会因旧记录立即触发封禁，新的言语攻击仍按再犯规则封禁。

验证覆盖真实模型合成样本、隔离 SQLite 下的处罚边界/事务/管理员入口/故障，以及后台桌面和移动端页面。此任务完成本地实现，不包含 GitHub 推送或生产部署。
