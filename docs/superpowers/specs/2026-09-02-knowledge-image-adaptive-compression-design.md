# 知识库图片自适应压缩设计

## 目标

知识库图片上传继续使用现有 Markdown 上传队列和后台接口，在不改变图片像素宽高的前提下尽量减小文件体积。

## 压缩策略

- JPG、JPEG、PNG、WebP 使用浏览器 Canvas 按原始 `bitmap.width` 和 `bitmap.height` 绘制，不做缩放或裁切。
- 依次尝试 WebP 质量 `0.82`、`0.74`、`0.65`。
- 目标体积为 1 MiB。遇到第一个不超过目标体积的结果时停止继续降低质量。
- 如果三个结果都超过目标体积，使用其中体积最小的结果。
- 只有选中的压缩结果小于原文件时才替换原文件，否则上传原文件。
- GIF 不进入 Canvas，保留动画、尺寸和原格式。
- 浏览器不支持 `createImageBitmap`、`File` 或 Canvas 编码失败时，回退上传原文件。

## 兼容边界

- 不修改上传接口、5 MB 服务端限制、鉴权、Markdown 插入格式和用户端渲染。
- 不改变多选、粘贴、拖拽、顺序插入、失败聚合及忙碌状态行为。
- 不清理已经上传的文件，包括本地验收产生的知识库图片。

## 测试与验收

- 契约测试确认不再存在最长边缩放常量或缩放计算。
- 契约测试确认 Canvas 宽高严格等于原始位图宽高。
- 契约测试确认质量阶梯、1 MiB 目标、最小结果选择、仅在更小时替换以及 GIF 直传。
- 运行知识库图片聚焦测试、全量 Node 契约测试、JavaScript 语法检查和 Blade 编译。
- 重启本地 Web 容器后确认 Octane、HTTP、Horizon 和 Redis 状态。
