# 自动化配置列表与 IP 管理

用户已确认紧凑列表方案，实施范围为本地代码与验证，不包含生产发布。

## 列表与排序

复用节点管理的展示 NodeID 自然排序：`code` 为空时使用数据库 ID，相同展示 ID 按数据库 ID 排序。先排序节点再按规范化域名合并，域名位置由其最靠前节点决定，关联节点也保持该顺序。IP 地址节点继续排除。

备用池使用一个带表头的列表，按域名及关联节点、当前 IP、状态及备用数量、操作分列。右侧常显「验证并开启 / 暂停自动化」「验证配置并匹配 DNS」「切换记录」「IP 管理」，保留原权限与操作锁。窄屏将按钮换行，所有操作保持可见。

## IP 管理

移除行内展开交互。「IP 管理」打开原生模态弹窗，显示域名、关联节点、当前 IP、检测状态与时间、异常原因、后台任务，以及原有备用列表和新增、编辑、测试、切换、删除操作。保持轮询更新，打开弹窗后从最新 groups 中取得域名数据，避免旧快照。

共用弹窗容器提供可访问名称、Escape/遮罩/关闭按钮、焦点限制与关闭后焦点恢复。保存失败和后台状态在弹窗内可见；表格仅在弹窗内部横向滚动。

## 视觉与验证

继续使用现有系统 HSL 主题变量和字体，统一间距、边界、表头、按钮高度与信息层级，不引入新主题。异常沿用 destructive，操作沿用 primary。桌面固定列对齐，较窄容器允许操作独占第二行，手机采用两列按钮。

用隔离 SQLite 验证排序和域名合并；通过已有自动化测试检查业务保护；用内存预览检查弹窗、数据更新、备用编辑、日志、键盘与桌面/手机布局。更新后台资源版本并运行缓存检查。
