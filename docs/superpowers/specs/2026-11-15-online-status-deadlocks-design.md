# 在线状态与统计死锁修复

用户在生产排障结论后要求立即修复，沿用已说明的统一锁顺序、缩小事务、增加死锁重试方案并发布。

## 证据与范围

生产 InnoDB 最近死锁（北京时间 2026-11-15 06:57:30）由 `StatUserJob` 的用户行共享锁与 `CleanupExpiredOnlineStatus` 的多用户更新构成。清理累计失败 66 次，各产生命令与调度两条错误。`UpdateAliveDataJob` 另有一次死锁后立即失败。三个文件的生产哈希与当前仓库一致。

修复三个任务的用户行锁粒度与顺序，以及管理后台把 Horizon 分钟数直接显示成小时的问题。历史邮件拒收、无效支付回调、权限拒绝不在本次变更范围。

## 设计

- `StatUserJob` 在整批事务之前按数值用户 ID 排序，整批事务最多尝试三次。保留账号删除共享锁与整批回滚，避免部分提交后队列重试重复累计流量。
- `UpdateAliveDataJob` 按用户 ID 排序数据库更新，并为整个数据库事务配置三次尝试。缓存数据保持原语义，数据库事务失败不会部分提交用户更新。
- 清理每次读取最多 1000 个候选用户 ID，每个用户在独立的最多三次尝试事务里更新，并在更新条件中重新检查 `online_count > 0` 与五分钟前的时间界限。这样不会跨用户持锁，也不会把候选读取后重新上线的用户置零。
- 管理后台把 Horizon 提供的保留分钟数除以 60 后传给原有 hours 翻译参数；10080 分钟显示 168 小时。更新已有资源版本链。
