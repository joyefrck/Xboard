# 安装包下载镜像迁移设计

**日期：** 2026-07-29  
**状态：** 已确认
**范围：** Xboard 管理后台、安装包下载接口、独立下载服务器 `47.80.3.248`

## 1. 背景与目标

当前 Android、macOS、Windows 三个安装包由 Xboard 主站直接输出。实测主站磁盘读取和应用负载正常，但公网传输存在大量重传，单连接通常只有数百 KB/s，用户侧可能进一步降到几十 KB/s。已购买的 300 Mbps 峰值带宽不能消除当前公网路径上的丢包与拥塞。

本次将安装包字节流迁移到 `47.80.3.248`，同时保留 Xboard 主站作为文件源和即时回退路径。目标如下：

- 下载请求继续经过 Xboard 完成版本校验、签名校验和统计。
- 正常情况下由独立下载服务器发送安装包，避免主站当前公网路径。
- 上传新版本后自动同步，不要求管理员手工登录服务器传文件。
- 镜像同步失败或下载服务器不可用时，自动回退主站，不阻断下载。
- 支持断点续传和标准 `Range` 请求。
- 不引入 CDN、对象存储或备案要求。

“返回后台”时管理 SPA 冷启动较慢属于另一个问题，不在本次实施范围内。

## 2. 当前链路

当前下载链路为：

1. 用户端或下载页获取 Laravel 临时签名地址。
2. `AppDownloadController` 校验版本状态、签名和本地文件。
3. 控制器写入 `AppDownloadLog`。
4. Laravel/Octane 通过 `response()->download()` 输出整个文件。

三个现有安装包均保存在 Xboard 的 `app_downloads` 本地磁盘。此路径继续作为文件源和回退路径，不在迁移后删除。

## 3. 方案概览

采用“Xboard 鉴权与统计，Nginx 镜像发送字节”的双层架构：

```text
管理员上传
    │
    ▼
Xboard 本地文件 + 版本记录
    │
    └── Horizon 异步 SFTP 同步 ──► 下载服务器 Nginx

用户下载
    │
    ▼
Xboard 签名下载接口
    ├── 校验、记录日志
    ├── 镜像就绪且健康：302 到短期镜像签名 URL
    └── 镜像未就绪或不可用：主站本地直出
```

Xboard 仍是业务入口和事实来源。独立服务器只保存可重新生成的镜像文件，不承载后台、数据库或业务 API。

## 4. 下载服务器设计

### 4.1 服务和目录

- 使用独立域名 `download.elephant111.com`，A 记录指向 `47.80.3.248`。
- 服务器位于无需中国大陆 ICP 备案的区域，整个方案保持无备案。
- 安装轻量 Nginx，仅监听该下载站点的 HTTP/HTTPS。
- 使用 Let's Encrypt 证书并启用自动续期。
- 镜像根目录为 `/srv/xboard-downloads/`。
- 关闭目录列表，不暴露真实上传目录结构以外的信息。
- 开启 `sendfile`，支持 `HEAD`、`Range` 和 `206 Partial Content`。
- 不改动服务器上现有的 sing-box、Docker DNS 或其他服务。

### 4.2 下载鉴权

镜像地址使用 Nginx `secure_link` 校验，包含：

- 相对文件路径；
- 过期时间；
- Xboard 与 Nginx 共享的高强度随机签名密钥。

Xboard 生成的镜像 URL 默认 10 分钟过期。签名无效或已过期时，Nginx 拒绝请求。共享密钥只进入两端生产环境配置，不写入代码仓库。

### 4.3 文件同步账户

Xboard 不使用 root 密码同步文件。下载服务器创建专用 SFTP 账户：

- 仅允许密钥认证；
- 权限限制在镜像目录；
- 禁止交互式 shell；
- 不授予 sudo；
- 私钥仅保存于 Xboard 生产环境的 secret/config 挂载中。

管理员提供的 root 密码只用于本次服务器初始化，不写入仓库、数据库或应用配置。

## 5. Xboard 数据与服务设计

### 5.1 镜像状态

在 `v2_app_artifacts` 增加以下字段：

| 字段 | 用途 |
| --- | --- |
| `mirror_status` | `local`、`pending`、`syncing`、`ready`、`failed` |
| `mirror_path` | 镜像服务器上的相对文件路径 |
| `mirror_error` | 最近一次同步失败的脱敏摘要 |
| `mirrored_at` | 最近一次成功同步时间 |

状态含义：

- `local`：尚未启用或无需镜像；
- `pending`：等待 Horizon 处理；
- `syncing`：正在上传；
- `ready`：远端文件校验完成，可用于下载；
- `failed`：最近一次同步失败，下载继续本地直出。

### 5.2 同步服务

新增镜像同步服务和 Horizon Job。生产 Web 容器没有 `ssh`、`scp`、`sftp` 或 `rsync` 命令，因此同步使用 PHP SFTP/Flysystem 适配器，不依赖 shell 工具。

同步流程：

1. 管理员上传成功，数据库事务提交后将版本置为 `pending` 并投递 Job。
2. Job 加锁，防止同一版本并发同步，将状态改为 `syncing`。
3. 从本地磁盘以流方式上传到远端临时文件，避免将整个安装包载入内存。
4. 校验远端文件大小；初始化迁移额外核对 SHA-256。
5. 通过原子重命名把临时文件切换为正式路径。
6. 写入 `mirror_path`、`mirrored_at`，状态改为 `ready`。
7. 失败时记录脱敏错误并改为 `failed`；Job 按退避策略有限重试。

上传临时文件不会被 Nginx 的正式下载路径引用。新文件确认就绪后才切换状态，因此用户不会下载到半个安装包。

### 5.3 替换和删除

- 替换安装包：新本地文件保存成功后重新进入 `pending`；旧镜像在新镜像就绪后清理。
- 删除版本：先使版本不可下载，再异步清理远端镜像；远端清理失败不阻塞后台删除，但保留错误日志供运维处理。
- 本地文件继续遵循现有引用计数和安全清理规则，不能因镜像成功而提前删除。

## 6. 用户下载链路

现有公开下载地址和客户端更新接口保持不变。

`AppDownloadController` 继续执行：

1. 校验 Laravel 相对签名、节流规则、版本发布状态和本地文件存在性。
2. 创建 `AppDownloadLog`，保持现有统计语义。
3. 当镜像功能开启、状态为 `ready` 且镜像健康时，返回 `302` 到短期 Nginx 签名地址。
4. 其他情况继续使用本地 `response()->download()`。

镜像健康检查使用短超时，并缓存 30–60 秒，避免每个用户请求都增加一次远端探测。探测超时、连接失败或文件不存在时直接走本地，不把错误暴露给用户。

为避免 302 后浏览器无法自动回到主站，只有健康检查通过的镜像才会被选中。紧急情况下通过 `APP_DOWNLOAD_MIRROR_ENABLED=false` 可以立即强制所有请求本地直出，无需修改数据库。

## 7. 上传新版本的后台交互

上传表单字段和操作步骤不变。上传完成后的反馈调整为：

- 首先提示“安装包已发布，正在同步到下载服务器”；
- 版本列表新增“镜像状态”列；
- 显示“同步中”“已同步”“同步失败”“本地直出”等状态；
- 同步失败时显示简短、脱敏的错误摘要，并提供“重新同步”按钮；
- 同步中或失败期间，用户下载自动走旧服务器，不中断服务；
- 替换安装包后自动重新同步，无需额外勾选。

后台 API 返回镜像状态及可展示的错误信息，并新增受现有后台权限保护的“重新同步”接口。页面通过现有刷新机制更新状态，不引入新的实时通信基础设施。

## 8. 初始迁移

上线顺序采用可回退方式：

1. 初始化下载服务器、专用 SFTP 账户、Nginx、TLS 和签名配置。
2. 部署数据库字段、同步 Job、后台状态和下载回退逻辑，但保持镜像开关关闭。
3. 将现有三个安装包标记为 `pending` 并同步。
4. 对本地和远端文件逐一核对文件名、大小和 SHA-256。
5. 验证有效签名、过期签名、`HEAD`、`Range`、完整下载和统计。
6. 开启镜像开关，小流量验证后保持启用。

任一步骤失败都保持本地下载路径可用。

## 9. 安全与运维

- root 密码、SFTP 私钥和签名密钥不得进入 Git、日志或后台页面。
- 同步错误必须脱敏，不能包含私钥路径、密码或完整连接配置。
- Nginx 只暴露下载目录，禁止目录遍历和符号链接逃逸。
- 镜像相对路径由服务端生成，不接受用户直接传入。
- 保留 Nginx access/error 日志和 Horizon Job 日志，便于区分鉴权失败、文件缺失和网络故障。
- 证书续期失败、磁盘使用率和同步失败需要可被现有运维方式检查。

## 10. 验收标准

### 10.1 自动化验证

- 数据迁移、模型字段和状态转换测试通过。
- 同步 Job 成功、失败、重试、并发锁和原子切换测试通过。
- 镜像签名与过期时间测试通过。
- 下载控制器仅在镜像就绪且健康时重定向，并始终保留下载日志。
- 镜像不可用、功能关闭或同步失败时本地回退测试通过。
- 替换、删除和手工重新同步测试通过。
- 后台能正确展示所有镜像状态和脱敏错误。

### 10.2 线上验证

- 三个现有包的远端大小和 SHA-256 与本地一致。
- 有效镜像 URL 返回 `200`，过期或篡改 URL 被拒绝。
- `Range: bytes=0-1048575` 返回 `206` 和正确的 `Content-Range`。
- Android、macOS、Windows 完整下载均能正常安装或通过既有校验。
- 下载后 `AppDownloadLog` 正常增加。
- 下载页和客户端更新检查无需改版即可使用新链路。
- 从至少两个不同网络测量下载速度，并与迁移前结果对比。
- 停止镜像 Nginx 或关闭镜像开关后，下载能回退主站。

## 11. 回滚

首选回滚方式是关闭 `APP_DOWNLOAD_MIRROR_ENABLED`。此操作立即停止生成镜像重定向，所有新请求恢复主站直出。

数据库新增字段、后台展示和远端文件可以暂时保留，不影响旧链路。只有在确认不再需要镜像后，才单独安排删除服务器配置和数据字段；本次上线不删除主站的三个安装包。

## 12. 不在本次范围

- CDN、OSS 或其他对象存储接入；
- 中国大陆备案和境内加速；
- 后台 SPA 静态资源缓存及“返回后台”卡顿修复；
- 修改用户端下载页面或客户端更新交互；
- 将安装包唯一源迁移出 Xboard 主站；
- 迁移下载服务器上已有的 sing-box 或 Docker 服务。
